## Steps
1. **Config (CustomerConfig.luau).** Fill `PAY_TABLE` and add multiplier constants, each line commented `-- PROPOSED (Jack)` (DEC-011 Q6, design §5.8):
   - base pay by order Category: Boba Teas 3, Coffee 2 (plus 1 for each of Iced and Sugar that is true), Hot Cocoa 2, Tea 2, Grab 1. Use the category strings that `ORDER_POOL` uses (grep `Category =` in the file; the pool items are Boba Teas / Custom Boba, Coffee / Regular, and the brownie). A multi-item order pays the sum.
   - `GRADE_MULT = { Perfect = 1.0, Close = 0.5 }`, `FAST_MULT = 1.5`, `FAST_FRACTION = 0.5`, `COMBO_STEP = 0.1`, `COMBO_CAP = 0.5`, `RESCUE_MULT = 1.5`, `RESCUE_FRACTION = 0.3`, `MIN_PAY = 1`.
   - `FIRST_SESSION_COUNT = 3` (TUNING) and `FIRST_SESSION_ORDERS`: #1 `{Category "Boba Teas", Item "Custom Boba", CustomInfo {Syrup Flavor "Classic Milk Tea", Tapioca Flavor "Normal"}, Size "Medium"}`, #2 Fudge Brownie, #3 `Regular` Coffee Size "Small" (design §4.4, Q4). Copy the exact field names from the `ORDER_POOL` entries.
2. **Rules.luau (pure).** Add `Rules.Payout(items, grade, fractionLeft, comboCount, scripted, rescue, config?) -> number` = `max(MIN_PAY, math.round(base * GRADE_MULT[grade] * speed * (1 + min(comboCount * COMBO_STEP, COMBO_CAP)) * (rescue and RESCUE_MULT or 1)))`, where `speed = FAST_MULT` when `scripted or fractionLeft >= FAST_FRACTION`, else 1 (design §3.5). `comboCount` is the number of consecutive Perfect serves before this one. Add `Rules.NextCombo(comboCount, grade) -> number` (Perfect +1, Close 0). Add `Rules.CanServe(isAssigned, fractionLeft, config?) -> boolean` (assigned barista always; anyone else only when `fractionLeft < RESCUE_FRACTION`). Add `Rules.PickAssignee(candidates, idleSince)` returning the clocked-in barista with a free slot who has been idle longest (design §4.3).
3. **Spec (CustomerService.spec.luau), money logic only (DEC-017).** Table tests: first Perfect scripted boba = 5; Perfect non-fast coffee = 2; Close = half rounded with min 1; combo 5 steps caps at +50%; Rescue x1.5; `NextCombo` Close resets to 0; `CanServe` at 0.31 false for a non-assignee, at 0.29 true; `PickAssignee` picks the longest idle. Add the R1 P3-10a test: every `ORDER_POOL` entry at every `SIZE_WEIGHTS` size resolves through the real `OrderSpec.FromOrderItem` to a spec.
4. **Stat.** ProfileTemplate `Statistics.CustomersServed = 0`.
5. **Assignment (init.luau).** When an NPC reaches `AtCounter`, call `_assign(npc)`: gather clocked-in players (`ShiftService:IsClockedIn`) with no ticket (`self._tickets[player] == nil`) and `OrderService:HasActiveOrder(player) == false`; skip all assignment while `OrderService:GetPendingCount() > 0`; pick with `Rules.PickAssignee` (track `idleSince[player] = os.clock()` set at clock-in and at ticket clear). If nobody qualifies, the NPC keeps waiting and `_assign` runs again on the next 1 s pacing tick. On assignment: set the patience clock then (`PatienceEnd = workspace:GetServerTimeNow() + total`, attribute `AssignedUserId = player.UserId`), not at arrival (design §4.5). Never give a barista the same spec twice in a row (re-roll up to 5 times with `Rules.PickOrder`).
6. **Order generation.** Orders come from `Rules.PickOrder` and `OrderSpec.FromOrderItem` (already used by the NPC). While `CustomersServed` for the assigned player is below `FIRST_SESSION_COUNT` (read `DataService` profile `Statistics.CustomersServed`; grep how StatisticsService reads it), the NPC order is `FIRST_SESSION_ORDERS[n+1]` and the NPC is `Scripted = true`: its patience does not tick (Q4). Customer #1 must be waiting within 5 s of spawn on a fresh profile: when the barista has `CustomersServed == 0`, assign the first NPC at the counter without waiting for the next tick.
7. **Bubble colour chip.** In `Npc.luau` `buildBubble`, add one small `Frame` (UICorner CORNER_FULL, size 14x14 px) left of the label whose `BackgroundColor3` is the syrup colour of the order (read it from the Menu syrup colours table that `Recipes.luau` uses at line ~101; grep `["Brown Sugar"] = Color3`). Coffee uses `Color3.fromRGB(204, 161, 135)`; Grab uses GRAY from `Styles`. No new colour tokens (DEC-013).
8. **Ticket table (the contract for M1.4f; copy exactly).** `CustomerService.Client.TicketChanged = Knit.CreateSignal()` (declare it as `OrderService` declares `NotepadUpdated`, grep line ~95). Fire `TicketChanged:Fire(player, ticket)` with:
   ```
   ticket = {
     Id = string,            -- npc.Model.Name (unique per NPC)
     NpcModel = Model,       -- the NPC model in workspace.Customers
     Label = string,         -- npc.Spec.Label
     Spec = { Category = string, Item = string, CustomInfo = {...}?, Size = string? },  -- the order item (plain data, no functions)
     PatienceEnd = number,   -- server time (GetServerTimeNow)
     PatienceTotal = number, -- seconds
     Scripted = boolean,
     Rescue = false,
   }
   ```
   or `nil` to clear. Fire on assignment, on serve, on walkout, on reassignment (to the new barista, and `nil` to the old one). When the NPC is below 30% patience and was rescued by a different player, fire `nil` to the assigned barista plus `DialogService:Notify` "<name> rescued your customer!".
9. **Serve prompt (Q2).** At `AtCounter`, create a `ProximityPrompt` named `ServePrompt` on the NPC `HumanoidRootPart`: ActionText "Serve", ObjectText = NPC label, HoldDuration 0, MaxActivationDistance 8, RequiresLineOfSight false. Set model attribute `PromptAction = "Serve"`; the client flips it to "Rescue" locally (M1.4f). On `Triggered(player)` run, in this order and with no yield between pick and destroy (design §4.6): (1) `ShiftService:IsClockedIn`; (2) distance from `player.Character.PrimaryPart` to the NPC root 10 or less; (3) `npc.State == "AtCounter"`; (4) `Rules.CanServe(npc.AssignedUserId == player.UserId, fractionLeft)`; (5) `OrderService:FindServeTools(player, { npc.Spec })`. `FindServeTools` already skips tools with `Served = true` (R1 P3-9); do not duplicate that.
10. **Perfect or Close.** Destroy the tool(s), compute pay with `Rules.Payout`, `CurrencyService:Modify(player, "BobaBucks", pay)`, `StatisticsService:IncrementStat(player, "CustomersServed")`, update the combo (`self._combo[player]`, session memory only), `DialogService:Notify` a toast `+N · Perfect · Fast · Combo ×n` (omit parts that do not apply), a `BillboardGui` "+N" over the NPC for 1.5 s (Styles tokens only), `npc:Leave("Served")` as Happy. Clear the ticket.
11. **Wrong (Q5).** `DialogService:Notify` with the first reason text from `FindServeTools`; keep the tool; do not touch the combo; the NPC plays nothing yet (NPC-LOOK adds Confused).
12. **Walkout.** On `CustomerLeft` with reason `"PatienceOut"`: clear the ticket, set that player's combo to 0, toast "Customer left. Combo lost." No BobaBucks are taken (design §3.4).
13. **Reassignment.** On `ShiftService.ClockedInChanged(player, false)` and `Players.PlayerRemoving`: if the player holds a ticket, clear it for them and call `_assign(npc)` again (patience keeps running, `PatienceEnd` unchanged). Nobody free means the NPC waits and re-assigns on the next tick.
14. **Robustness (continued play).** Every new callback runs inside `pcall`; an error warns once and never stops the pacing thread. The service stays disabled-safe when the contract is missing.
15. Run `stylua` then `gate` on all six files, and the lune shim for the spec if available (as M1.4core did; record that it is a shim).
