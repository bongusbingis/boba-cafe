# M1.5b: Recipe card on the HUD order ticket
Model: sonnet   Studio: no   Depends on: UI-CONV (done), M1.5a (done), M1.5cd (done)   Size: M

## Goal
While a player works an order, the HUD shows that order's steps (Cup → Milk → Syrup → Tapioca, and so on). Each step is ticked as the held drink gains it, the current step is marked, and the card says when the drink is Wrong or Close. This is player-facing, so it must match the existing UI exactly (DEC-013).

## Steps
1. Get the spec through `KitchenGuidance.ResolveSpec(currentOrder)`. If it returns nil, render no card (the ticket stays as today).
2. Track the equipped tool on the local character:
   - listen to `ChildAdded` and `ChildRemoved` on the character;
   - listen to `AttributeChanged` on the equipped Tool;
   - disconnect everything in cleanup;
   - recompute within 0.2 s of any change.
3. Call `OrderSpec.StepState(spec, tool)` and render one row per `Steps` entry. Each row is done, current or pending, with the labels from `Steps`. Show the Wrong and Close states exactly as design §3.8 describes. Take the step order from `Steps`/`StepState`; never hard-code it (Q14 makes ice and sugar order-free).
4. On a phone, collapse per §3.8 and STYLE §2.2 (detect the device the way existing HUD code does).
5. Use only the tokens, components, springs and copy rules in STYLE.md. Copy the row and tick visuals from the closest existing component STYLE.md names. If no existing pattern fits a needed element, STOP-AND-ASK.
6. Add a story that renders five fixed states: pending, current (step 2), all done, Wrong, and Close.
